# CleoDoc 开发计划

> 本文件是实施状态、任务顺序和发布门的唯一来源。
>
> 产品范围见 [PRD](./PRD.md)，系统边界见[技术架构](./TECHNICAL_ARCHITECTURE.md)。

## 1. 版本策略

- **v0.1：CLI 核心 MVP，已完成。** 已通过 LLM 创作、资料管理、本地 RAG、持久化恢复和跨平台 CLI 发行闭环验收。
- **v0.2：Electron 桌面 UI。** 将 v0.1 已完成能力迁移到安全、可用的 Electron + React 界面，仅补充桌面产品成立所必需的 Markdown/TXT 作品与资料阅读能力。
- **v0.3：创作工作室能力扩展。** 承接 CDM/TipTap、Draft、Git/语义 Diff、知识图、阶段 Agent 和新格式导入导出等未进入 v0.2 的能力。

v0.2 不改变作品事实格式、知识语义、Agent 创作流程或版本模型。CLI 继续保留并与 Desktop 复用同一套 Core/Application Service。

## 3. v0.2 产品边界

### 3.1 目标

v0.2 完成以下桌面闭环：

```text
创建或打开项目
→ 查看 Markdown/TXT 作品
→ 导入并查看 Markdown/TXT 资料
→ 建立索引并执行检索
→ 配置 Provider 与模型
→ 与主笔对话并使用现有 Tool
→ 审批并保存生成文档
→ 压缩上下文
→ 重启应用并恢复 Conversation 继续工作
```

### 3.2 明确不做

- CDM 正文迁移、正式 CDM v1 和节点级编辑。
- TipTap/ProseMirror 富文本编辑器和正文编辑工具栏。
- Draft 写入、文本统计和 ChangeSet。
- Git 版本管理、命名版本、恢复历史和文档语义 Diff。
- 知识图、自动事实抽取、人物/设定审批和关系检索。
- 持久化阶段 Agent、写作任务中心、Checkpoint 和自动长篇生成。
- 新 Provider、统一模型调用记录界面和独立问题诊断界面。
- 文件夹批量导入、DOCX、PDF、EPUB、OCR 和新的导出格式。
- 云同步、账号系统、多人协作、插件系统和 ANN 向量索引。

现有 ModelCall 审计和 Debug 日志继续保留在 Core/CLI 中，但 v0.2 不为其开发桌面页面。

### 3.3 第一版 UI 参考边界

v0.2 采用已确认的深色三栏工作室作为第一版视觉与信息架构参考：

- 左侧为功能导航和当前作品/资料列表。
- 中间为 Markdown/TXT 只读阅读区。
- 右侧为主笔对话区。
- 顶部展示当前项目/文档、模型和新建 Conversation 入口。
- 必要运行状态显示在其所属页面，不建设独立监控中心。

参考 UI 中超出 v0.2 范围的控件直接隐藏，不制作不可用按钮、占位页面或模拟交互，包括编辑工具栏、大纲、场景卡、人物设定、任务中心、AI 专用建议卡、版本历史和插入正文等入口。

## 4. v0.2 实施阶段

### 4.1 Electron 兼容性与桌面工程基线

需要实现：

- 建立可启动、可构建和可打包的 Electron + React 应用。
- 验证现有项目、`node:sqlite`、sqlite-vec、`node-llama-cpp`、Embedding Worker、Provider 和软件配置在开发版与安装版中运行。
- 明确应用资源、默认配置、本地模型和用户项目的路径边界。
- 保持 CLI 可独立运行。

检查点：

- Desktop 可以启动、退出并打开现有 v0.1 项目。
- SQLite、sqlite-vec、本地 Tokenizer/Embedding 和真实 Provider 均通过桌面环境冒烟测试。
- 安装版不要求最终用户另外安装 Node.js。
- 本地模型和原生依赖不会因打包丢失或从错误路径加载。
- CLI 的 build、typecheck、lint 和测试不回退。

### 4.2 桌面应用基础、项目隔离与安全操作

需要实现：

- 建立 Desktop 可复用的项目级 Application Service 与明确的打开、关闭和资源释放生命周期。
- Renderer 只使用经过 Schema 校验的白名单产品能力，不直接操作文件、SQLite、模型密钥或底层运行时。
- 使用系统文件/目录选择窗口完成项目打开和资料导入。
- 支持写入、覆盖、删除和项目指令修改的用户审批。
- 支持聊天、压缩、索引和 Embedding 等长任务的状态、取消与退出处理。
- v0.2 同一应用实例只保持一个活动 Project；切换项目前先关闭当前 Project。

检查点：

- 所有操作都绑定当前项目，不能访问或修改其他项目。
- 项目切换后 Conversation Runtime、审批和后台任务不会串入新项目。
- 未经批准或被拒绝的操作不会产生写入。
- 取消和退出不会损坏正文、资料、消息或索引事实源。
- 外部链接、Markdown 和模型输出不能获得本地项目权限。
- 用户错误不泄露密钥、任意绝对路径或底层堆栈。

### 4.3 项目创建、打开与状态管理界面

需要实现：

- 项目首页、最近项目列表、新建项目和打开项目。
- 展示当前项目名称、目录和基本状态。
- 关闭当前项目和切换项目。
- 处理项目不存在、清单无效、数据库损坏或版本不支持等现有错误。

检查点：

- 新项目可以通过 UI 创建并进入工作区。
- 现有 v0.1 项目可以原样打开，不静默迁移或改写正文。
- 重启应用后可以从最近项目继续。
- 无效项目和不支持的数据库不会被自动删除、降级或重建。
- 项目关闭后数据库、Worker 和对话运行时均得到释放。

### 4.4 作品目录与正文阅读界面

需要实现：

- 以左侧目录展示当前项目的 Markdown/TXT 作品文件。
- 中间阅读区安全渲染 Markdown，并按原始换行显示 TXT。
- 展示文件名、项目内路径、大小和更新时间等已有元数据。
- 支持刷新外部变化。
- UI 化已有的 Markdown 文档创建、删除和生成结果保存能力。
- 为作品读取服务补充 `.txt` 列出与读取；v0.2 不增加 TXT 编辑或写入语义。

检查点：

- `.md` 和 `.txt` 作品都能选择并正确显示中文、英文、Emoji 和换行。
- 阅读不会改变原文件内容、编码或换行。
- Markdown 中的脚本和危险内容不会执行。
- 删除、覆盖和保存生成结果沿用现有审批与原子写入规则。
- 路径穿越和符号链接不能逃逸项目范围。
- 不出现编辑工具栏、自动保存、字数统计、版本号或 CDM 迁移入口。

### 4.5 资料管理与资料阅读界面

需要实现：

- 展示项目资料列表及已有状态。
- 通过文件选择导入 TXT/Markdown，或粘贴文本创建资料。
- 展示输入编码和资料基本信息。
- 安全阅读 Markdown/TXT 资料。
- 支持重命名、删除、重复内容和同名冲突反馈。

检查点：

- 现有 UTF-8、GB2312、GBK、GB18030 导入规则保持一致。
- 相同规范化内容不重复导入，同名 title 明确拒绝。
- 重命名不改变资料内容和索引归属。
- 删除必须确认，失败不损坏资料事实源。
- 不增加文件夹批量导入、个人资料库或新资料格式。

### 4.6 Provider、模型与软件配置界面

需要实现：

- Provider 正式适配模块完成前，以 `openai-compatible` 作为 DeepSeek 调试入口。
- 设置界面只配置 Base URL、API Key 和模型名称；当前模型限定为发行配置中的 `deepseek-v4-flash`。
- Base URL 和模型选择写入用户软件配置；API Key 通过 Electron `safeStorage` 使用操作系统凭据能力加密持久化。
- Renderer 只获得 API Key 是否已配置的状态，不能读取或回显密钥。

检查点：

- Desktop 重启后可以继续使用已保存的 API Key，不要求用户再次输入。
- 用户配置最终生效为 `openai-compatible`、填写的 Base URL 和 `deepseek-v4-flash`。
- API Key 不明文进入项目、软件 YAML、数据库、日志、Git 或界面回显。
- 操作系统安全凭据能力不可用时拒绝持久化，不允许退化为明文保存。
- UI 生效值与 Core 实际配置一致。
- 不新增 Provider 适配、模型发现、连接诊断、调用记录或其他软件配置界面。

### 4.7 AI 主笔聊天与 Conversation 管理界面

需要实现：

- 三栏工作室右侧提供主笔聊天区。
- 发送消息、展示历史消息、停止生成和保留未发送输入。
- 新建、列出、恢复 Conversation，并展示最近对话。
- 第一阶段在打开项目后列出该项目全部 Conversation；点击后进入可继续交流的当前对话视图，展示最近 20 条 `user`/`assistant` 消息，并可返回原列表。
- 当前阶段只在已有 Conversation 的当前对话视图底部显示输入框，用于继续对话；暂不提供新建 Conversation。不同 Conversation 的未发送草稿在界面生命周期内分别保留。
- LLM 的 Reasoning 在生成时自动展开并流式展示，完成后自动折叠，再流式展示回复 Content。
- 历史页标题使用 `conversations.title`；Assistant Reasoning 以默认折叠的“思考 ▸”区域显示在正文气泡上方，展开前不渲染 Reasoning 正文。
- 将已有项目文档加入后续对话上下文。
- 将生成结果保存为项目文档。

检查点：

- 可以完成真实模型对话并在重启后恢复 Conversation。
- 不同 Conversation 的消息和 Session 保持隔离。
- Conversation 列表和当前消息查询不跨项目；最近 20 条在数据库层有界查询，不先向 Renderer 返回完整消息日志。
- System、Tool 和内部消息字段不进入历史界面；Reasoning 仅在非空时提供折叠入口，且不包含在 Assistant 聊天气泡中。
- 取消生成不删除此前已保存消息。
- 页面切换、压缩或失败不会清空未发送输入。
- 保存生成结果遵守创建/覆盖审批和项目路径限制。

### 4.8 流式输出、Reasoning、Session 与上下文管理界面

需要实现：

- 实时展示流式 Content，并与 Reasoning 分区展示。
- 展示当前上下文预算状态。
- 支持自动/手动压缩、压缩中状态和失败重试。
- 查看 Conversation 下的 Session 和同一 Conversation 已关闭历史。
- 压缩期间禁止提交，但保留用户正在编辑的输入。

检查点：

- 流式输出不重复、不乱序，Reasoning 不被当作正式正文。
- 压缩成功后在新 Session 延续同一 Conversation。
- 压缩失败、取消或退出不删除旧 Session 和原始消息。
- 历史回查不跨 Conversation 自动继承，也不跨项目访问。

### 4.9 Tool Call 状态与用户审批界面

需要实现：

- 显示读取正文、查询历史和检索资料等 Tool 的简洁执行状态。
- 自动执行现有允许静默执行的只读 Tool。
- 对文档写入、覆盖和项目指令修改显示目标、操作类型、必要预览及批准/拒绝入口。
- 展示成功、失败、取消和拒绝状态，不把原始 Tool JSON 当作普通聊天内容。

检查点：

- 只读 Tool 正常返回模型，写入 Tool 未批准时不改变事实源。
- 审批只对当前 Project、Conversation 和当前 Tool Call 有效。
- 切换/关闭项目后旧审批失效。
- 无效参数、路径越权和拒绝都不会产生部分写入。
- RAG Tool Result Message 仍能还原实际提供给模型的证据。

### 4.10 本地索引、Embedding、混合检索与恢复界面

需要实现：

- 展示总体和单份资料索引状态。
- 触发 Chunk/FTS 重建和 Embedding 生成，展示进度并支持取消。
- 提供现有普通、语义和混合检索界面。
- 展示结果资料、命中范围和必要来源信息。
- 查看现有 Embedding 模型信息并执行 Embedding 测试。
- 对失败资料提供现有重试/重建入口。

检查点：

- 可以从 UI 完成导入、索引、检索闭环。
- 精确名称、资料原文和近义描述均能召回对应资料。
- 检索严格限定当前项目和 material 范围。
- 取消、失败和重建不会修改原资料。
- 删除资料后 Chunk、FTS 和向量均不可再检索。
- 普通 UI 检索不持久化为模型证据审计。
- 不增加正文索引、ANN 或新的向量后端。

### 4.11 项目指令与 Revision 历史界面

需要实现：

- 查看当前项目指令和实际 Revision。
- 查看历史 Revision 及其内容。
- 经确认恢复历史 Revision。
- 展示并审批模型提出的追加或整体替换请求。

检查点：

- SQLite Revision 继续作为唯一事实源，不读取项目目录中的 `AGENTS.md`。
- 恢复历史产生新 Revision，不删除或改写既有历史。
- 未批准、被拒绝或失败的修改不改变当前指令。
- 项目切换后指令和审批不串用。

### 4.12 桌面打包、跨平台验证与发布

需要实现：

- 生成 Windows、macOS 桌面发行包和 Linux 可运行制品。
- 正确包含默认配置、本地 Embedding 模型、sqlite-vec 与 `node-llama-cpp` 平台依赖。
- 从安装版创建、打开和继续使用项目。
- 明确应用配置、缓存与用户项目边界；升级或卸载不自动删除用户项目。

检查点：

- 在源码环境之外从真实安装产物完成 v0.2 垂直闭环。
- Windows、macOS 和 Linux 制品均能启动并打开已有项目。
- 本地索引、语义检索、真实对话、Tool 审批和重启恢复均通过。
- 原生依赖、GGUF 和 Worker 入口在打包后可用。
- CLI 与 Desktop 可以先后打开同一项目；v0.2 不支持同时写入同一项目。

## 5. 阶段依赖与发布门

```mermaid
flowchart LR
    A["Electron 兼容性"] --> B["桌面安全与项目生命周期"]
    B --> C["项目与阅读工作区"]
    C --> D["资料与配置"]
    D --> E["聊天与 Session"]
    E --> F["Tool 审批"]
    F --> G["索引与检索"]
    G --> H["项目指令"]
    H --> I["跨平台桌面发布"]
```

- 兼容性验证未通过前，不以静态页面替代真实 Core 接入。
- 每个页面必须消费同一 Application Service，不在 Renderer 复制领域逻辑。
- 每一阶段完成时必须同时验证成功、失败、取消、项目切换和重启恢复路径中与该阶段相关的行为。
- 不为后续版本提前创建不可用入口、空白页面、平行数据模型或占位数据库表。

## 6. v0.2 最终验收

必须使用真实桌面发行包完成：

1. 创建或打开现有项目，并查看 Markdown/TXT 作品。
2. 导入并查看中英文 Markdown/TXT 资料。
3. 重建 Chunk、FTS 和 Embedding，并执行普通与语义检索。
4. 配置 OpenAI-compatible，与真实模型对话。
5. 让模型调用 RAG Tool 检索资料并调用文档 Tool 读取作品。
6. 经用户审批保存生成文档，并在阅读区查看结果。
7. 触发上下文压缩，退出应用并恢复 Conversation 继续工作。
8. 查看并恢复项目指令历史 Revision。
9. 删除资料并确认其 Chunk、FTS 和向量均不可再检索。
10. 在 Windows、macOS 和 Linux 发行物完成核心启动与项目打开验证。

验收要求：没有跨项目泄漏；未批准操作不会写入；失败、取消和退出不会损坏正文、资料、消息或索引事实源；Desktop 不复制 v0.1 Core 逻辑；CLI 行为不回退。

## 7. v0.3 顺延范围

以下能力从原 v0.2 规划顺延到 v0.3，实施前仍需重新评审和确定内部顺序：

- 正式 CDM v1、现有 Markdown 作品迁移和节点级文档服务。
- TipTap/ProseMirror 编辑器、CDM 双向适配、批注和自动保存。
- Draft 写入、文本统计、幂等写入和 ChangeSet 审批。
- Git 隐藏版本引擎、命名版本、安全恢复和 CDM 语义 Diff。
- 人物、地点、事件、关系、时间线、伏笔、知识图、事实抽取和设定审批。
- 可恢复阶段 Agent、写作任务中心、AgentJob、Checkpoint 和长篇创作流程。
- 文件夹批量导入、DOCX/PDF 解析以及 Markdown/TXT/DOCX/EPUB 导出。
- 新 Provider 接入、跨厂商模型调用记录与统一问题诊断界面。
- 个人资料库、跨 Conversation 历史检索、云同步、多人协作、OCR、插件和 ANN。

v0.3 不因本文件列出这些能力而自动获得确定范围；开始规划时必须重新确认产品边界、依赖和验收标准。
