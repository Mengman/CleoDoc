# CleoDoc 桌面 UI 结构设计

> 状态：当前确认的结构设计，用于后续 UI 重构与功能接入。
>
> 本文只确定界面层级、区域职责和共享关系，不冻结视觉样式、尺寸、颜色、间距或具体控件。任何设计图仍然只是阶段性参考。

## 1. 设计目标

CleoDoc 桌面界面分为三个层级：窗口标题栏、全局导航区和功能区。

设计需要满足以下目标：

- 窗口级操作、全局功能导航和具体业务内容职责分离。
- 作品和资料共用文档阅读区域与 AI 聊天窗口。
- 作品和资料可以同时打开，并由统一标签页管理。
- 切换功能时不丢失已经打开的作品、资料或聊天上下文。
- 设置界面使用独立布局，占据完整功能区。

## 2. 总体层级

```text
CleoDoc 桌面窗口
├─ Windows-titlebar
│  ├─ 软件 Logo
│  ├─ 软件菜单
│  └─ 窗口控制：最小化、最大化/还原、关闭
└─ 应用主体
   ├─ 导航区
   └─ 功能区
      ├─ 作品界面
      ├─ 资料界面
      └─ 设置界面
```

`Windows-titlebar` 位于窗口顶部。导航区和功能区位于标题栏下方，并共同占据剩余窗口空间。

## 3. Windows-titlebar

`Windows-titlebar` 是窗口级区域，始终显示，不随功能区切换。

包含：

- CleoDoc 软件 Logo。
- 软件菜单，例如 File、Edit、View、Window。
- 当前操作系统提供的窗口控制按钮：最小化、最大化/还原、关闭。

标题栏只负责软件级菜单和窗口操作，不承载项目导航、文档标签页或具体业务功能。

## 4. 导航区

导航区位于应用主体最左侧，始终显示，负责切换功能区当前展示的内容。

当前确认的主要功能入口为：

- 作品。
- 资料。
- 设置。

导航按钮只改变功能区的当前界面，不直接承载作品列表、资料列表、设置表单或业务状态详情。

设置入口在视觉上可以与作品、资料入口分组，但仍然属于同一个全局导航区。

查询等其他 v0.2 能力的具体导航归属尚未在本文确定。在得到新的 UI 决策前，不因其业务存在而自动增加新的顶级导航入口。

## 5. 功能区

功能区位于导航区右侧，占据应用主体其余全部空间。功能区根据当前导航状态切换为作品界面、资料界面或设置界面。

作品和资料不是两个独立的完整功能界面，而是同一个创作工作区中两种左侧导航内容。点击“作品”或“资料”时，只切换功能区最左侧的导航块，中间文档工作区和右侧 AI 聊天窗口不切换、不重建，也不根据该导航选择改变当前内容。

创作工作区持有以下长期存在的状态：

- 已打开的作品与资料标签页。
- 当前激活的文档标签页。
- 中间文档阅读区域。
- 右侧 AI 聊天窗口及其当前上下文。

作品和资料之间的切换只改变左侧导航块的业务内容，不创建两套阅读区或聊天区，也不向中间和右侧组件传递作品/资料模式。

## 6. 功能区－作品界面

作品界面采用三栏结构。

```text
作品界面
├─ 左侧：作品导航
├─ 中间：共享文档工作区
│  ├─ 文档标签页
│  └─ 作品内容展示/编辑区域
└─ 右侧：共享 AI 聊天窗口
```

### 6.1 作品导航

左侧展示当前项目的作品和作品内部导航，用于选择需要打开的作品内容。

该区域只负责作品集合与结构导航，不直接保存正文内容，也不创建独立的正文副本。

### 6.2 共享文档工作区

中间区域用于展示或编辑作品内容，并通过标签页同时打开多个作品文档。

标签页属于作品和资料共用的统一标签集合。切换到其他功能时，已经打开的作品标签页保持不变。

“展示/编辑区域”是该区域的长期结构定位。按照当前版本边界，v0.2 只实现 Markdown/TXT 阅读以及已有安全文档操作的 UI 化，不在此阶段引入 TipTap、CDM 正文编辑或新的 Draft 写入能力。

### 6.3 共享 AI 聊天窗口

右侧展示 AI 聊天窗口。聊天窗口与资料界面共用，不因作品和资料功能切换而创建新的聊天实例。

聊天所使用的项目、Conversation 和文档上下文必须由实际业务状态决定，不能仅依据界面当前显示内容推断或复制一套平行状态。

当前 Conversation 采用列表与当前对话两级视图。项目打开后，列表按最近活动顺序展示当前项目全部 Conversation；点击一项进入可继续交流的当前对话视图，顶部显示返回箭头和数据库 `conversations.title`。当前对话视图只加载最近 20 条 `user` 与 `assistant` 可见消息，User 气泡居右，Assistant 气泡居左。

当前阶段暂不开放新建 Conversation，因此 Conversation 列表不显示输入框。用户打开已有 Conversation 后，输入框固定在当前对话视图底部，用于继续该 Conversation。每个已打开 Conversation 分别维护临时输入草稿；切换 Conversation 时不清空，切回后恢复。草稿只保存在当前 Renderer 生命周期内，发送成功后清空，发送失败则恢复。

Assistant 的 `reasoning_content` 去除首尾空白后非空时，在正文气泡上方显示“思考 ▸”控制项，小三角位于文字右侧。Reasoning 默认折叠，用户展开前不渲染正文；展开后显示“思考 ▾”，正文使用灰色文字且不包含在聊天气泡中。“思考”控制项使用亮灰色，字号为聊天内容字号的三分之二。每条 Assistant 消息独立维护折叠状态，离开当前对话视图后恢复默认折叠。

模型生成期间的 Reasoning 增量例外：收到第一段 Reasoning 时自动展开并实时显示；Reasoning 结束或第一段 Content 到达时自动折叠，随后在 Assistant 气泡中流式展示 Content。持久化完成后的消息仍遵循默认折叠规则。

## 7. 功能区－资料界面

资料界面同样采用三栏结构，并复用作品界面的中间文档工作区和右侧聊天窗口。

```text
资料界面
├─ 左侧：资料列表
├─ 中间：共享文档工作区
│  ├─ 原有作品标签页继续保留
│  ├─ 新打开的资料标签页
│  └─ 资料阅读区域
└─ 右侧：共享 AI 聊天窗口
```

### 7.1 资料列表

左侧展示当前项目已经导入的资料，用于选择需要阅读的资料。

资料列表与作品导航占用相同的功能区左栏位置，但两者是不同功能下的内容投影。

### 7.2 打开资料

用户打开一份资料时：

1. 当前已经打开的作品标签页保持不变。
2. 在共享文档工作区中创建或激活对应的资料标签页。
3. 中间区域显示该资料内容。
4. 右侧继续使用同一个 AI 聊天窗口。

打开资料不能替换、关闭或重新创建原有作品标签页。

### 7.3 资料阅读边界

v0.2 的资料阅读支持 Markdown 和纯文本。资料阅读与作品阅读共用渲染基础设施，但必须保留不同的文档类型和业务身份，不能因为共用视图而混淆作品与资料的操作权限。

## 8. 功能区－设置界面

设置界面占据完整功能区，不显示作品/资料文档工作区和 AI 聊天窗口。

```text
设置界面
├─ 左侧：设置大项
└─ 右侧：当前设置项的具体内容
```

### 8.1 设置大项

左侧展示设置分类，用于切换右侧的具体设置内容。

### 8.2 设置内容

右侧展示当前设置分类对应的表单、状态和操作。

进入设置界面时，作品、资料标签页和聊天状态保留在内存中，但不在设置功能区显示。离开设置界面后，应恢复进入设置前的文档工作区和聊天状态。

## 9. 共享状态与局部状态

### 9.1 全局界面状态

- 当前功能：作品、资料或设置。
- 进入设置前的工作区功能。
- 当前活动项目。

### 9.2 文档工作区共享状态

- 已打开标签页的有序集合。
- 每个标签页的文档类型：作品或资料。
- 当前激活的标签页。
- 每个标签页的阅读位置和临时界面状态。
- 作品正文在共享阅读区域内独立纵向滚动，不带动左侧导航或右侧聊天窗口滚动。

文档工作区状态由作品界面和资料界面共同消费。设置界面不展示该状态，但也不清除该状态。

每个已打开的作品标签页提供关闭按钮。关闭非活动标签页时保持当前文档；关闭活动标签页时优先激活其右侧相邻标签页，没有右侧标签页时激活左侧标签页；关闭最后一个标签页后回到未选择文档状态。

### 9.3 AI 聊天共享状态

- 当前 Conversation 和 Session。
- 当前消息流和未发送输入。
- 当前明确选择的作品、资料或其他上下文。
- 正在执行的流式响应、Tool Call、审批或后台任务状态。

聊天状态由作品界面和资料界面共同消费。界面切换不能导致 Conversation Runtime、审批或后台任务跨项目串联。

### 9.4 功能局部状态

- 作品界面持有作品导航的展开、选择等状态。
- 资料界面持有资料列表的选择、筛选等状态。
- 设置界面持有当前设置大项和表单临时状态。

局部状态不得复制作品正文、资料原文、Conversation 或项目数据库状态。

## 10. 建议的组件职责

以下名称用于表达结构职责，不要求后续代码必须采用完全相同的命名：

```text
DesktopShell
├─ WindowTitlebar
├─ PrimaryNavigation
└─ FeatureArea
   ├─ CreativeWorkspace
   │  ├─ WorksSidebar 或 MaterialsSidebar
   │  ├─ DocumentWorkspace
   │  │  ├─ DocumentTabBar
   │  │  └─ DocumentViewer
   │  └─ ChatPanel
   └─ SettingsWorkspace
      ├─ SettingsNavigation
      └─ SettingsContent
```

其中 `CreativeWorkspace` 表示作品和资料共用的工作区外壳。作品与资料的差异只存在于左侧导航块；`DocumentWorkspace` 和 `ChatPanel` 不消费当前选择的是作品还是资料，始终保持同一实例和同一状态来源。

## 11. 结构约束

- 不为作品和资料分别创建两套文档标签页状态。
- 不为作品和资料分别创建两套 AI 聊天状态。
- 作品/资料导航状态只允许控制左侧导航块，不得驱动中间文档区或右侧聊天区切换内容。
- 切换导航功能不等于关闭文档、项目或 Conversation。
- 打开资料不能覆盖当前作品标签页。
- 进入设置不能清空文档工作区或聊天状态。
- 设置界面不嵌套在作品或资料三栏布局内。
- Renderer 只消费白名单 Typed IPC，不因 UI 分区而直接访问文件系统、SQLite 或项目绝对路径。
- 本文不授权增加尚未确认的按钮、面板或功能入口；具体 UI 元素仍需在开发前取得用户授权。

## 12. 本文不确定的内容

以下内容不由本结构设计决定，后续需要单独确认：

- 各区域的具体宽度、是否允许拖动和最小尺寸。
- 标签页的视觉形式、溢出处理和重启恢复策略。
- 查询能力最终位于顶级导航、资料界面还是其他入口。
- AI 聊天窗口是否允许折叠或调整宽度。
- 设置分类的具体列表和排列顺序。
- v0.3 编辑器进入共享文档工作区后的具体交互。
