# CleoDoc 桌面 UI 结构设计

> 状态：当前确认的结构设计，用于后续 UI 重构与功能接入。
>
> 本文只确定界面层级、区域职责和共享关系，不冻结视觉样式、尺寸、颜色、间距或具体控件。任何设计图仍然只是阶段性参考。

> v0.2 收尾阶段只维护当前界面。v0.3 才引入本文件第 4.6 节的 UI 技术方案并迁移已有页面；任何新增可见元素仍需得到用户明确授权。

## 1. 设计目标

CleoDoc 桌面界面分为四个层级：窗口标题栏、全局导航区、功能区和状态栏。

设计需要满足以下目标：

- 窗口级操作、全局功能导航和具体业务内容职责分离。
- 作品和资料共用文档阅读区域与 AI 聊天窗口。
- 作品和资料可以同时打开，并由统一标签页管理。
- 切换功能时不丢失已经打开的作品、资料或聊天上下文。
- 设置界面使用独立布局，占据完整功能区。

## 2. 总体层级

```text
CleoDoc 桌面窗口
├─ Windows-titlebar
│  ├─ 软件 Logo
│  ├─ 软件菜单
│  └─ 窗口控制：最小化、最大化/还原、关闭
├─ 应用主体
   ├─ 导航区
   └─ 功能区
      ├─ 作品界面
      ├─ 资料界面
      └─ 设置界面
└─ 状态栏
```

`Windows-titlebar` 位于窗口顶部，状态栏固定在窗口底部。导航区和功能区位于两者之间，并共同占据剩余窗口空间。

## 3. Windows-titlebar

`Windows-titlebar` 是窗口级区域，始终显示，不随功能区切换。

包含：

- CleoDoc 软件 Logo。
- 软件菜单，包括 File、Edit、View、外观、Window；“外观”中提供主题选择。
- 当前操作系统提供的窗口控制按钮：最小化、最大化/还原、关闭。

标题栏只负责软件级菜单和窗口操作，不承载项目导航、文档标签页或具体业务功能。

## 4. 导航区

导航区位于应用主体最左侧，始终显示，负责切换功能区当前展示的内容。

当前确认的主要功能入口为：

- 作品。
- 资料。
- 设置。

导航按钮只改变功能区的当前界面，不直接承载作品列表、资料列表、设置表单或业务状态详情。

设置入口在视觉上可以与作品、资料入口分组，但仍然属于同一个全局导航区。

查询等其他 v0.2 能力的具体导航归属尚未在本文确定。在得到新的 UI 决策前，不因其业务存在而自动增加新的顶级导航入口。

## 4.5 状态栏

状态栏固定在窗口最底部，横跨导航区和功能区。它用于展示当前桌面应用的简短运行状态；没有任务时显示“就绪”。

聊天生成、上下文压缩、索引和 Embedding 等长任务进入界面化后，其进度、可取消状态和结果提示统一显示在状态栏中。状态栏不替代任务中心，当前阶段不增加独立面板、历史记录或新的操作入口。

## 4.6 UI 技术方案（v0.3）

### 技术栈与职责

Renderer 在现有 Electron + React + TypeScript 基础上采用以下组合：

- **Tailwind CSS**：构建期样式工具和语义 token 的消费层，负责布局、响应式规则与页面级样式组合。
- **shadcn/ui**：按需生成并维护在仓库中的基础组件源码。它是 CleoDoc 的通用组件层，不作为外部黑盒主题库使用。
- **Radix UI**：提供 Dialog、AlertDialog、DropdownMenu、Popover、Select、Tabs、ScrollArea、Tooltip 等无障碍交互原语；shadcn 已采用的 Radix primitive 直接复用，不建立重复的通用组件体系。

三者只能位于 `apps/desktop` Renderer。Main、Preload、CLI 和 `packages/*` 不得依赖 DOM、Tailwind、shadcn/ui 或 Radix UI。

阶段一已完成 Renderer 构建接入：Tailwind 通过 Renderer Vite 插件处理，并继续由 `index.html` 外链加载；`components.json` 和 `components/ui/` 是 shadcn 源码的唯一配置与目录位置。Renderer 的 `@` 别名指向其 `src` 目录，供组件源码使用。当前只导入 Tailwind 的 theme 与 utilities，不导入 Preflight，避免其全局重置影响尚未迁移的手写页面。

阶段三已按需生成 Button、Input、Textarea、Select、Tabs、Dialog、AlertDialog、DropdownMenu、Popover、Tooltip、ScrollArea、Progress、Badge 和 Toast（Sonner）。这些组件使用 Radix UI、`class-variance-authority`、`clsx`、`tailwind-merge` 与 `tw-animate-css`。除已获授权的设置页主题下拉菜单外，它们尚未导入业务页面。Tailwind 的 `dark:` 变体由 Renderer 的 `data-theme="dark"` 驱动；Toast 同样读取该属性，不使用 `next-themes` 或浏览器存储。

### 主题与视觉 token

主题使用语义 CSS variables，而非在页面中直接使用具体颜色。最少定义：

- `background`、`surface`、`surface-raised`、`foreground`、`muted-foreground`、`border`。
- `primary`、`accent`、`destructive`、`warning`、`success` 及相应前景色。
- 字体、字号、行高、圆角、间距、阴影、层级和动效时长。

同一套 token 在 `:root` 与 `:root[data-theme="dark"]` 中分别定义 Light 与 Dark 模式；System 偏好由 Main 根据操作系统主题解析为其中一种模式。启动时 Main 先设置窗口背景，Renderer 在首次 React 渲染前设置 `data-theme`，避免未来消费 token 的页面出现错误主题闪烁。

主题偏好保存于应用状态的 `state.yaml`，取值为 `light`、`dark` 或 `system`，缺省为 `system`。Preload 只暴露 Schema 校验后的读取与修改接口、启动主题和系统主题变化事件。窗口菜单提供“外观 → 主题”，设置页提供“外观 → 主题”下拉菜单；两处读取和修改同一偏好，选择后立即更新窗口和 Renderer。旧手写页面在迁移前不强行改用 token，避免重复样式改造。

“毛玻璃感”使用不透明渐变 surface、细边框、柔和阴影和层级色差实现。不得依赖真实透明背景或 `backdrop-filter`；阅读区、编辑器和长列表优先保证文字对比度、滚动性能和跨平台一致性。

### 基础组件范围

v0.3 首先只引入以下最小组件集：Button、Input、Textarea、Select、Tabs、Dialog、AlertDialog、DropdownMenu、Popover、Tooltip、ScrollArea、Progress、Badge 和 Toast。

组件应保留业务无关性：它们只接收显示、焦点、键盘和回调状态；项目路径、数据库、模型密钥、任务逻辑和 IPC 调用仍由现有业务组件及 Typed IPC 边界负责。

### 迁移策略

1. 先建立主题 token 和基础组件，再迁移窗口标题栏、导航、项目首页、阅读区、聊天、设置、授权控件和状态栏。
2. 页面迁移保持现有 Application Service、Typed IPC、项目隔离和业务状态，不创建平行数据模型。
3. 单个页面完成迁移后删除被替代的手写通用样式与重复组件；不得长期混用两套通用按钮、表单、弹窗或主题系统。
4. 组件库模板不授权增加功能入口、导航、占位卡或模拟数据；所有新增可见 UI 仍需用户明确授权。
5. UI 框架基线完成后，页面按本文件的结构顺序单独迁移和验收。每次迁移继续复用现有业务组件、Application Service 与 Typed IPC，只替换通用视觉和无障碍交互层，不复制项目、资料、聊天或主题状态。

当前已完成窗口骨架、项目首页和创作工作区外壳迁移：`App` 仍是唯一的 `DesktopShell`，标题栏、全局导航、功能区容器和状态栏已经使用语义 token 与 Tailwind utilities。未打开项目时的项目首页复用既有 Typed IPC，并使用 Button 与 Input 呈现已确认的 API Key 配置、新建项目和打开项目操作。创作工作区已使用三栏 Grid 承载作品/资料左栏、共享文档区与共享聊天区，切换作品/资料时只替换左栏。文档、聊天和列表的内部模块尚未迁移，不得因为前三阶段迁移而提前调整其业务结构。

### 编辑器与版本控制边界

TipTap 不属于通用 UI 组件层。v0.4 中 TipTap/ProseMirror 负责编辑器文档状态、选区、命令和扩展；shadcn/ui 与 Radix UI 只负责其周边工具栏、菜单、浮层、标签页、确认框和状态反馈。

Git 版本服务也不依赖 UI 框架，但版本列表、恢复确认、Diff 浏览与错误反馈必须复用 v0.3 的基础组件和主题 token。

## 5. 功能区

功能区位于导航区右侧，占据应用主体其余全部空间。功能区根据当前导航状态切换为作品界面、资料界面或设置界面。

作品和资料不是两个独立的完整功能界面，而是同一个创作工作区中两种左侧导航内容。点击“作品”或“资料”时，只切换功能区最左侧的导航块，中间文档工作区和右侧 AI 聊天窗口不切换、不重建，也不根据该导航选择改变当前内容。

创作工作区持有以下长期存在的状态：

- 已打开的作品与资料标签页。
- 当前激活的文档标签页。
- 中间文档阅读区域。
- 右侧 AI 聊天窗口及其当前上下文。

作品和资料之间的切换只改变左侧导航块的业务内容，不创建两套阅读区或聊天区，也不向中间和右侧组件传递作品/资料模式。

## 6. 功能区－作品界面

作品界面采用三栏结构。

```text
作品界面
├─ 左侧：作品导航
├─ 中间：共享文档工作区
│  ├─ 文档标签页
│  └─ 作品内容展示/编辑区域
└─ 右侧：共享 AI 聊天窗口
```

### 6.1 作品导航

左侧展示当前项目的作品和作品内部导航，用于选择需要打开的作品内容。

该区域只负责作品集合与结构导航，不直接保存正文内容，也不创建独立的正文副本。

### 6.2 共享文档工作区

中间区域用于展示或编辑作品内容，并通过标签页同时打开多个作品文档。

标签页属于作品和资料共用的统一标签集合。切换到其他功能时，已经打开的作品标签页保持不变。

“展示/编辑区域”是该区域的长期结构定位。按照当前版本边界，v0.2 只实现 Markdown/TXT 阅读以及已有安全文档操作的 UI 化，不在此阶段引入 TipTap、CDM 正文编辑或新的 Draft 写入能力。

### 6.3 共享 AI 聊天窗口

右侧展示 AI 聊天窗口。聊天窗口与资料界面共用，不因作品和资料功能切换而创建新的聊天实例。

聊天所使用的项目、Conversation 和文档上下文必须由实际业务状态决定，不能仅依据界面当前显示内容推断或复制一套平行状态。

当前 Conversation 采用列表与当前对话两级视图。项目打开后，列表按最近活动顺序展示当前项目全部 Conversation；点击一项进入可继续交流的当前对话视图，顶部显示返回箭头和数据库 `conversations.title`。当前对话视图只加载最近 20 条 `user` 与 `assistant` 可见消息，User 气泡居右，Assistant 气泡居左。

Conversation 列表与当前对话视图都保留聊天输入区：列表提交首条消息时创建并进入新 Conversation，当前对话视图用于继续所选 Conversation。每个已打开 Conversation 和列表新建输入分别维护临时草稿；切换时不清空，切回后恢复。草稿只保存在当前 Renderer 生命周期内，发送成功后清空，发送失败则恢复。

Assistant 的 `reasoning_content` 去除首尾空白后非空时，在正文气泡上方显示“思考 ▸”控制项，小三角位于文字右侧。Reasoning 默认折叠，用户展开前不渲染正文；展开后显示“思考 ▾”，正文使用灰色文字且不包含在聊天气泡中。“思考”控制项使用亮灰色，字号为聊天内容字号的三分之二。每条 Assistant 消息独立维护折叠状态，离开当前对话视图后恢复默认折叠。

模型生成期间的 Reasoning 增量例外：收到第一段 Reasoning 时自动展开并实时显示；Reasoning 结束或第一段 Content 到达时自动折叠，随后在 Assistant 气泡中流式展示 Content。持久化完成后的消息仍遵循默认折叠规则。

## 7. 功能区－资料界面

资料界面同样采用三栏结构，并复用作品界面的中间文档工作区和右侧聊天窗口。

```text
资料界面
├─ 左侧：资料列表
├─ 中间：共享文档工作区
│  ├─ 原有作品标签页继续保留
│  ├─ 新打开的资料标签页
│  └─ 资料阅读区域
└─ 右侧：共享 AI 聊天窗口
```

### 7.1 资料列表

左侧展示当前项目已经导入的资料，用于选择需要阅读的资料。用户可通过资料区的导入操作选择单个 TXT 或 Markdown 文件；每项资料提供原地重命名操作，按 Enter 保存、按 Esc 取消，以及删除操作。删除必须先经系统确认窗口确认；重命名或删除失败使用独立系统错误窗口提示，资料列表保持不变。

资料列表与作品导航占用相同的功能区左栏位置，但两者是不同功能下的内容投影。资料重命名只更新资料 title；已打开资料标签页同步显示新标题，资料内容和物理文件不变。资料删除成功后，对应标签页关闭，资料文件与关联索引、Embedding 一并删除。

### 7.2 打开资料

用户打开一份资料时：

1. 当前已经打开的作品标签页保持不变。
2. 在共享文档工作区中创建或激活对应的资料标签页。
3. 中间区域显示该资料内容。
4. 右侧继续使用同一个 AI 聊天窗口。

打开资料不能替换、关闭或重新创建原有作品标签页。

### 7.3 资料阅读边界

v0.2 的资料阅读支持 Markdown 和纯文本。资料阅读与作品阅读共用渲染基础设施，但必须保留不同的文档类型和业务身份，不能因为共用视图而混淆作品与资料的操作权限。

## 8. 功能区－设置界面

设置界面占据完整功能区，不显示作品/资料文档工作区和 AI 聊天窗口。

```text
设置界面
├─ 左侧：设置大项
└─ 右侧：当前设置项的具体内容
```

### 8.1 设置大项

左侧展示设置分类，用于切换右侧的具体设置内容。

当前分类包括“模型 API”和“外观”。“外观”中的“主题”使用下拉菜单提供“跟随系统”“浅色”“深色”三个选项，与窗口菜单中的“外观 → 主题”保持同一设置。

### 8.2 设置内容

右侧展示当前设置分类对应的表单、状态和操作。

进入设置界面时，作品、资料标签页和聊天状态保留在内存中，但不在设置功能区显示。离开设置界面后，应恢复进入设置前的文档工作区和聊天状态。

## 9. 共享状态与局部状态

### 9.1 全局界面状态

- 当前功能：作品、资料或设置。
- 进入设置前的工作区功能。
- 当前活动项目。

### 9.2 文档工作区共享状态

- 已打开标签页的有序集合。
- 每个标签页的文档类型：作品或资料。
- 当前激活的标签页。
- 每个标签页的阅读位置和临时界面状态。
- 作品正文在共享阅读区域内独立纵向滚动，不带动左侧导航或右侧聊天窗口滚动。

文档工作区状态由作品界面和资料界面共同消费。设置界面不展示该状态，但也不清除该状态。

每个已打开的作品标签页提供关闭按钮。关闭非活动标签页时保持当前文档；关闭活动标签页时优先激活其右侧相邻标签页，没有右侧标签页时激活左侧标签页；关闭最后一个标签页后回到未选择文档状态。

### 9.3 AI 聊天共享状态

- 当前 Conversation 和 Session。
- 当前消息流和未发送输入。
- 当前明确选择的作品、资料或其他上下文。
- 正在执行的流式响应、Tool Call、审批或后台任务状态。

聊天状态由作品界面和资料界面共同消费。界面切换不能导致 Conversation Runtime、审批或后台任务跨项目串联。

### 9.4 功能局部状态

- 作品界面持有作品导航的展开、选择等状态。
- 资料界面持有资料列表的选择、筛选等状态。
- 设置界面持有当前设置大项和表单临时状态。

局部状态不得复制作品正文、资料原文、Conversation 或项目数据库状态。

## 10. 建议的组件职责

以下名称用于表达结构职责，不要求后续代码必须采用完全相同的命名：

```text
DesktopShell
├─ WindowTitlebar
├─ PrimaryNavigation
├─ FeatureArea
   ├─ CreativeWorkspace
   │  ├─ WorksSidebar 或 MaterialsSidebar
   │  ├─ DocumentWorkspace
   │  │  ├─ DocumentTabBar
   │  │  └─ DocumentViewer
   │  └─ ChatPanel
   └─ SettingsWorkspace
      ├─ SettingsNavigation
      └─ SettingsContent
└─ StatusBar
```

v0.3 的组件目录可在上述结构之外增加 `components/ui/`，用于放置 shadcn/ui 生成并由本仓库维护的基础组件。业务组件不得反向放入该目录。

其中 `CreativeWorkspace` 表示作品和资料共用的工作区外壳。作品与资料的差异只存在于左侧导航块；`DocumentWorkspace` 和 `ChatPanel` 不消费当前选择的是作品还是资料，始终保持同一实例和同一状态来源。

## 11. 结构约束

- 不为作品和资料分别创建两套文档标签页状态。
- 不为作品和资料分别创建两套 AI 聊天状态。
- 作品/资料导航状态只允许控制左侧导航块，不得驱动中间文档区或右侧聊天区切换内容。
